## 1. Дерево процессов — `ptree.py`

Программа получает информацию о процессах из виртуальной файловой системы `/proc`.

Для каждого процесса определяются:
- PID — идентификатор процесса;
- PPID — идентификатор родительского процесса;
- UID — идентификатор пользователя;
- STATE — состояние процесса;
- RSS — объём используемой физической памяти.

Запуск программы:

```bash
python3 ptree.py
```

**Результат:** программа успешно вывела дерево процессов текущего пользователя.

## 2. Создание процессов — `runner.py`

Запуск программы:

```bash
python3 runner.py 3 sleep 1
```

**Результат:**
- Созданы три дочерних процесса.
- Все три процесса завершились с кодом возврата `0`.
- Время выполнения каждого процесса составило примерно `1.004` секунды.

В программе используются системные вызовы `fork()`, `execvp()` и `waitpid()`.

## 3. Zombie-процесс — `zombie.py`

Запуск программы:

```bash
python3 zombie.py
```

**Результат:**
- PID родительского процесса: `1556`.
- PID дочернего процесса: `1557`.
- Дочерний процесс завершился раньше родительского.
- Родитель некоторое время не вызывал `wait()`.
- Затем родитель вызвал `waitpid()` и забрал статус завершения ребёнка.

Для подтверждения состояния zombie необходимо проверить состояние дочернего процесса командой `ps` во время ожидания родителя.

## 4. Orphan-процесс — `orphan.py`

Запуск программы:

```bash
python3 orphan.py
```

**Результат:**
- PID родительского процесса: `1563`.
- PID дочернего процесса: `1564`.
- Первоначальный PPID ребёнка: `1563`.
- Новый PPID ребёнка: `1501`.

После завершения родительского процесса дочерний процесс был переназначен другому процессу.

## 5. Copy-on-Write — `cow.py`

Запуск программы:

```bash
python3 cow.py
```

**Результаты измерения RSS:**

| Этап | RSS |
|---|---:|
| Родитель до `fork()` | 87196 KB |
| Ребёнок сразу после `fork()` | 84152 KB |
| Ребёнок после изменения списка | 84344 KB |
| Родитель после завершения ребёнка | 87388 KB |

После изменения списка RSS дочернего процесса увеличился на `192 KB`.

Это согласуется с механизмом Copy-on-Write, при котором страницы памяти копируются при необходимости изменения. Однако одних значений RSS недостаточно, чтобы точно определить объём скопированных страниц.
